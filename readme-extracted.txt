CSI-QA-Testing: Developer Guide This is a guide for playwright regression suite on the CSI (RCSI) web application. This document explains how the project is organized, how to configure credentials, and how to run tests locally or on BrowserStack. 1. Quick start Prerequisites: Node.js (LTS) Npm for package install npm install Playwright browsers installed npx playwright install Copy “ .env.example ” keys to “ .env ” in the project root and fill in values For credential value details, see Section 3 Run the full suite locally: npm test For suite running details, see Section 6 2. Project folder structure High-level layout of the test suite project: CSI-QA-testing/ tests/csi/ (Playwright spec files: one folder per app module) pages/csi/ (Page Object Models (POMs) for UI interactions) pages/BasePage.ts (Shared base class for POMs) fixtures/csi/ (Custom Playwright fixtures: login + module pages) utils/csi/ (Test data builders, credentials, bulk-upload helpers) data/csi/ (Static JSON + PDF fixtures used by tests) storage/ (Runtime state value store) playwright.config.ts (Playwright runner settings) browserstack.yaml (BrowserStack cloud run settings) .env.example (Template for environment variables) Where tests live All CSI specs are under `tests/csi/&lt;ModuleName&gt;/`. Each module maps to a product area in the app. E.g. `SalesAndBilling.spec.ts`. Test data JSON defaults data (non-secret) and PDF fixtures used as uploads live under ` data/csi/ ` Module-specific builders and run time generated values are in `utils/csi/*TestData.ts`. Bulk Excel templates are created at runtime under `playwright/.cache/` where needed. `storage/userCounter.json` is a persisted counter for unique user names in Account Management tests. Set the lastUserNumber value as the max user append number created till now . Example: There are 2 user accounts created till now user+1@domain.com and user+2@domain.com . Now, lastUserNumber will be 2 . When the test suite creates more users (Eg: user+3@domain.com ) in the Account Management test module, it will automatically update the lastUserNumber as 3 . 3. Environment variables (.env) Copy `.env.example` to `.env`. CSI_BASE_URL : Target application URL for all tests. Example: https://rcsi-tst.example.com CSI_TEST_EMAIL / CSI_TEST_PASSWORD : Super admin account credentials CSI_ORG_TEST_EMAIL / CSI_ORG_TEST_PASSWORD : Organization manager account credentials CSI_ORG_USER_TEST_EMAIL / CSI_ORG_USER_TEST_PASSWORD : Organization user account credentials CSI_PHISING_ADMIN_TEST_EMAIL /CSI_PHISING_ADMIN_TEST_PASSWORD: Phishing module admin account credentials CSI_INCIDENT_REPORTER_TEST_EMAIL / CSI_INCIDENT_REPORTER_TEST_PASSWORD : Incident reporter account credentials CSI_INCIDENT_HANDLER_DISPLAY_NAME : Display name of incident handler CSI_SYSTEM_OWNER_TEST_EMAIL / CSI_SYSTEM_OWNER_TEST_PASSWORD : System owner account credentials CSI_SECURITY_REPORT_ADMIN_EMAIL / CSI_SECURITY_REPORT_ADMIN_PASSWORD : Security Report Admin account credentials CSI_TRAINING_PHISING_SYS_OWNER_TEST_EMAIL / CSI_TRAINING_PHISING_SYS_OWNER_TEST_PASSWORD : System Owner who only has Training and Phishing access BROWSERSTACK_USERNAME and BROWSERSTACK_ACCESS_KEY: Credentials to run test on Browserstack CI: Number of parallel workers in playwright Set value to “1” for best test performance, but slow Set value to “4” for finishing test parallelly fast, but might overload CPU 4. Test modules and case tree Specs are grouped by product module. `tests/csi/auth/` is not a product module : it only verifies login redirect and home navigation. Auth (login only : not a feature module) tests/csi/auth/login.spec.ts redirects to login, then to home after valid credentials Account Management tests/csi/accountManagement/AccountManagement.spec.ts manual add user AM-027 : bulk upload AM-045 : organization MFA AM-050 : user deactivation and reactivation Sales and Billing tests/csi/salesAndBilling/SalesAndBilling.spec.ts Navigate to Package Management and create package Navigate to Sales Order and create sales order Navigate to Sales Partner list and create sales partner SB-062 : invoice PDF matches on-page preview SB-056 : restricted hub module access Training tests/csi/training/Training.spec.ts TR-001 : create course distribution TR-025 : course report PDF export TR-033 : course dashboard manager view Phishing tests/csi/Phising/Phising.spec.ts Create a phishing test from template PH-020 : phishing dashboard view PH-024 : email template creation Policy Management tests/csi/PolicyManagement/PolicyManagement.spec.ts PM-001 : clone template, edit docx, distribution, submit for review PM-010 : approve pending policy PM-016 : distribute-now and acknowledgement PM-024 : submit major policy update PM-026 : policy update approval IT Asset Management tests/csi/ITAssetManagement/ITAssetManagement.spec.ts IA-001 : add client machine asset IA-020 : client machine asset state lifecycle IA-003 : bulk client machine upload IA-011 : purchase order creation IA-016 : edit client machine asset IA-025 : create, edit, assign user, view Incident Report tests/csi/IncidentReport/IncidentReport.spec.ts IR-005 : reporter dashboard IR-001 : assign Incident Reporter role IR-011 : handler assignment and reporter verification IR-012 : comment thread, PDF upload, download, reply IR-013 : ticket status Open through Closed Security Report tests/csi/SecurityReport/SecurityReport.spec.ts SR-014 : darkweb report download from request history SR-001 : attack surface dashboard view SR-005 : attack surface scan request 5. Playwright configuration Headless mode In `playwright.config.ts`, `use.headless` controls whether the browser window is visible during the run. headless: true : no visible browser UI , tests run in the background. headless: false : Chromium opens on screen so you can watch live test Current repo setting: headless is false (browser UI shows on local runs) Playwright Browsers Only one Playwright project is active: chromium (Desktop Chrome). Firefox, WebKit, and mobile projects are commented out in the config. BrowserStack runs Chrome on Windows 11 per `browserstack.yaml` (browserName: chrome, browserVersion: latest). 6. Running tests NOTE: Running the test on browserstack requires it’s credentials in .env file All tests Local Playwright: npm test BrowserStack (cloud): npm run test:browserstack Single spec file Local: npx playwright test IncidentReport.spec.ts BrowserStack: npm run test:browserstack -- IncidentReport.spec.ts Single test inside a spec Use the test title (case ID or name) with `-g`: npx playwright test -g &quot;AM-050&quot; BrowserStack example with full path: npm run test:browserstack -- tests/csi/accountManagement/AccountManagement.spec.ts -g &quot;AM-050&quot;
